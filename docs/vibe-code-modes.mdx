# 两种模式：Plan（规划）与 Build（执行）

> 同一个对话框，Agent 可能处于两种模式。**模式决定它"能不能写文件"**，不是模型能力差异，也不是 AI 偷懒。

快速判断：输入框旁的模式胶囊显示 `Plan`（或 规划/Architect）= 只读；显示 `Build`（或 执行/Code/Auto）= 可写。

如果你看到 AI 回复"当前处于规划模式（只读阶段），禁止进行文件写入或系统变更"，不是它拒绝干活，而是模式选错了。本文说明两种模式的区别、切换方法和使用场景；反馈纪律见[氛围编程](/docs/vibe-code)。

## 一、两种模式对照

GIS Agent 接入的编码 Agent（如 OpenCode）通常会把模式归为两类：

| 维度 | Plan（规划） | Build（执行） |
| :--- | :----------- | :------------ |
| 常见叫法 | 规划 / Architect / Ask（不同 Agent 叫法不同） | 执行 / 构建 / Code / Auto / Execute |
| 读文件、搜索、分析 | 可以 | 可以 |
| 写文件、改代码、系统变更 | **不可以（只读）** | **可以** |
| 典型输出 | 方案、步骤、风险、改动清单 | 代码、文件、命令、预览 |
| 适合 | 需求澄清、架构设计、影响面分析、评审 | 方案已确认、落地实现、修 bug |
| 风险 | 低（不动现场） | 中高（会改文件，需要验收） |

## 二、为什么会卡在"规划模式"

用户常遇到这样的回复：

> 系统当前仍明确处于规划模式（只读阶段）……禁止我进行任何文件写入或系统变更……请在客户端界面中将当前模式从 Plan 切换为可执行模式。

这不是 AI 拒绝干活，也不是它在"请示"；**Plan 模式在系统层禁用了写入工具，模型无法靠对话指令解除**。你对它说"你可以直接改""我授权你写"，都不会生效——约束在模式层，不在提示词层。

常见触发：

* 新建会话时沿用了上次的 Plan 偏好，或创建时没注意模式；
* 手动把模式切成了 Plan（规划/Architect）；
* 当前是历史会话/只读会话，写入本来就被禁用；
* 该 Agent 只暴露了 Plan 类模式，没有可写模式。

## 三、怎么切换（30 秒）

1. **看模式胶囊**：在输入框右下角（新对话页和对话页都有）找到带滑杆图标的按钮，上面显示当前模式名（如 `Plan`）。部分布局在标题栏。
2. **点开选执行模式**：在"模式"菜单里选 `Build`（也可能叫"执行/构建/Code/Auto/Execute"，以你的 Agent 为准）。
3. **回复"继续"**：同一会话内切换即可，上下文、已上传文件、已生成代码通常都还在，不需要重述需求；如果发现上下文丢了，再把计划贴过去。也可以说"按上面的计划执行"。
4. **切不动怎么办**：
   * 按钮是灰的：AI 正在回复，等它停下来再切；
   * 看不到模式胶囊：可能是只读/历史会话，或该 Agent 没有暴露模式；新建会话，在发送前选 Build；
   * 切完仍说 Plan：确认胶囊文字已变成 Build；没变就刷新/重试，仍不行再新开会话并把计划贴过去。

> AI 只能看到对话，看不到你的界面；它建议"切换模式或新开会话"是通用说法。GIS Agent 支持**会话内切换**，优先原地切，切换失败再新开。

**两个容易混淆的概念：**

* **Plan 模式 ≠ 只读会话**：页面出现"仅可查看历史记录"提示、输入框不可用时，是会话级只读（历史会话/Agent 不一致），不是切模式能解决的，需要新建会话。
* **模式是会话级的**：你在 A 会话切到 Build，不会自动改 B 会话；新会话开始前再看一眼模式胶囊，别假设它会继承上次选择。

## 四、什么时候用哪个

* **先 Plan 再 Build**：需求还很虚、要动多个文件/数据库、要先看影响面、要做架构或风险评审时，先在 Plan 里只读分析，拿到改动清单和验收标准，再切 Build 执行。
* **直接 Build**：需求明确、改动小、只是改文案/样式/一个函数，直接在 Build 里做，省一轮。
* **推荐循环**：`Plan 只读分析 → 人工确认 → Build 执行 → 预览验收`；大改或回归问题再切回 Plan 分析，确认后继续 Build。

一句话原则：**Plan 用来"想清楚"，Build 用来"做出来"；不要让 Plan 干 Build 的活，也不要在 Build 里边想边大改。**

## 五、常见误区

* **"AI 不肯干活"**：先看模式，不要先怀疑模型能力。
* **"我已经说'你可以改'了"**：聊天指令不能覆盖系统模式；必须在界面上切。
* **"Plan 模式也能生成代码"**：它可以在消息里展示代码，但不会落盘；看到代码不等于文件已改。
* **"切换 Build 就一定能写"**：还要看工作区权限、只读会话、工具是否可用；报错就按[预览排障](/docs/preview-error)贴原文。
* **"每次都要先 Plan"**：简单任务直接 Build；复杂任务才值得先规划。
* **"删对话重来"**：删了上下文和现场都没了；先切模式，切不动再新开（和[氛围编程](/docs/vibe-code)的"删对话=删现场"是同一条纪律）。
* **"CLI 里按 Tab 能切，网页上也可以"**：不同 Agent 的快捷键只在其 CLI 里有效；Web 端以模式胶囊为准。

## 六、可直接复制的两句话

规划阶段：

```text
当前先不要改文件。请只读分析，给我：1) 要改哪些文件/模块；2) 风险和影响面；3) 验收标准。
我确认后再执行。
```

执行阶段：

```text
已切换到 Build 模式，按上面的计划直接改文件并运行验证；
完成后给我改动清单、diff/预览和自检结果。
```

***

**使用提示：** 卡住时先看输入框旁的模式胶囊：`Plan` 是只读，`Build` 是可写；切到 Build 后回复"继续"即可。模式选对后，再按[氛围编程](/docs/vibe-code)的反馈纪律推进。
