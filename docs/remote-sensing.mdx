## 投影预处理

> 把 墨卡托投影 / 高斯-克吕格投影 等投影坐标系的数据，先处理成 **EPSG:4326（WGS84 经纬度）** 或 **EPSG:4490（CGCS2000 经纬度）** 的 GeoTIFF，再交给 AI，会极大提升处理效率。

### 为什么要先转成 4326 / 4490

核心原因在于**前端显示本身就需要 4326 / 4490 这类经纬度坐标**（MapLibre 取 WGS84 经纬度，Cesium 只用 EPSG:4326），而入库、切瓦、出图只是中间过程。

| 数据现状 | AI 需要多做的工作 | 结果 |
| :------- | :---------------- | :--- |
| 3857 / 高斯分带等投影坐标 | 判断投影与分带 → 换带 → 重投影 → 再对齐前端范围 | 反复对话修正，容易出错 |
| 已是 4326 / 4490 的 GeoTIFF | 直接入库、切瓦、加载 | 一轮到位 |

具体会踩的坑：

1. **分带截断**：高斯 3 度带（如 `CGCS_2000_3_Degree_GK_Zone_39`）只覆盖 3 个经度，跨带区域会被切开，AI 往往会当成"数据范围就这么大"。
2. **单位混用**：投影坐标的单位是米，经纬度的单位是度。AI 在写缓冲区半径、变化图斑面积阈值、缩放层级时，一旦单位判断错，结果会偏几个数量级。
3. **无符号带号无法判别**：`unnamed / 未命名` 的数据，AI 只能靠数值范围猜投影，猜错就整幅偏移。
4. **多一轮往返**：即使最后瓦片会重投影到 3857，前端加载、图斑回绘、坐标点击取位这些环节仍然全部回到经纬度，不如一开始就统一。

### 怎么做

先用 `gdalinfo` 确认源数据的空间参考系，再重投影。**如果源数据是 `unnamed`，必须先补上正确的源坐标系（`gdal_translate -a_srs` 或 `gdalwarp -s_srs`），否则重投影结果一定错**。

```bash
# 1. 查看空间参考系与四至范围
gdalinfo 2025年度.tif

# 2. 缺参考系时先定义（按数据实际情况填，别猜）
gdal_translate -a_srs EPSG:4527 2025年度.tif 2025年度_src.tif

# 3. 重投影到 4490（国内成果口径）或 4326（Web 显示口径）
gdalwarp -s_srs EPSG:4527 -t_srs EPSG:4490 -r bilinear -of GTiff \
    2025年度_src.tif 2025年度_4490.tif

# 4. 校验：Coordinate System 应为 geographic，四至应落在 -180~180 / -90~90
gdalinfo 2025年度_4490.tif
```

常用 EPSG 码：

| EPSG | 含义 | 适用 |
| :--- | :--- | :--- |
| 4326 | WGS84 经纬度 | Web 地图、Cesium、通用交换 |
| 4490 | CGCS2000 经纬度 | 国内测绘与行业成果口径 |
| 3857 | Web 墨卡托 | 前端瓦片切片，不建议作为入库成果 |
| 4527 | CGCS2000 3 度带带号 39 | 高斯分带投影（源数据常见） |

**注意事项：**

* 导出必须是 **GeoTIFF（.tif）**，保留地理信息；PNG/JPG/WebP 会丢坐标，等于白做。
* 4326 与 4490 在 Web 制图精度下差异可忽略（米级以内），但**行业成果交付一般要求 4490**，入库建议统一用 4490，前端出图时再由平台重投影。
* 分类影像（如土地利用/地类图斑栅格）重投影时把 `-r` 换成 `near`（最邻近），用 bilinear 会产生不存在的中间类别值。
* 两期数据必须转到**同一个** EPSG，否则仍然对不齐。

> 这一步人工做完，后面 AI 的入库、发服务、前端显示基本一轮就能跑通；不做的话，大部分对话轮次都会消耗在"坐标系又不对了"上。

## AI自动处理

接下来就可以和 AI 按照SKILL 组合的方式对话了 , 直接和AI对话即可. 一般常见的场景有下面几种:
1. 常规
   1. 入库     postgis-cli SKILL 触发导入
   2. 发服务   postgis-service-cli 触发发服务
   3. 显示     maplibre-common / cesium-common 显示
2. 视觉类
   1. 遥感比对:   死绝识别 + 空间分析
   2. 遥感提取:   视觉识别 + 图像分割

### 视觉比对

### 显示

由于前端只能支撑3857等主流投影, 如果是非3857 (墨卡托投影的数据), 需要进一步和AI对话将其处理成前端可以直接使用的格式

> 你有没有把 tiff 统一处理成3857墨卡托投影呀, maplibre必须统一坐标系
