# 遥感影像

> 遥感数据的标准流程是  上传数据 => 入库 => 发服务 => 前端显示
> 成败的关键在数据的质量与校验上

## 人工前置

这一步的数据如果用户提前校验后,后面的AI自动处理会很顺利

> 可能会出现以下场景
> 1. A 未命名  B 高斯投影  =>  2个都高斯
> 2. A 经纬度  B 高斯投影  =>  2个要么都是高斯 要么都是经纬度
> 3. A 未命名  B 未命名   =>  无法预料结果

## AI自动处理

接下来就可以和 AI 按照SKILL 组合的方式对话了 , 直接和AI对话即可. 一般常见的场景有下面几种:
1. 常规
   1. 入库     postgis-cli SKILL 触发导入
   2. 发服务   postgis-service-cli 触发发服务
   3. 显示     maplibre-common / cesium-common 显示
2. 视觉类
   1. 遥感比对:   死绝识别 + 空间分析
   2. 遥感提取:   视觉识别 + 图像分割

### 视觉比对

> 实现同一区域、不同时相遥感影像的自动化对比分析。工具支持用户上传不同时间段两期影像数据，自动识别区域地类变化范围、绘制变化图斑边界、标准化标注地类代码及名称，最终输出标准化Excel成果数据表及文字分析报告。

### 服务

针对遥感数据发服务有2种方式:
1. 标准的PG  postgis_raster模块 => ST_AsPNG出图 => postgis_gateway 网络服务
2. 个人用户的文件夹服务, 本地本轮对话 有个 uuid,  如果生成到本地 就会走下面的情况

   `https://gisagent.mapgis.com/files/{WS_uuid}/{folder_name}/{z}/{x}/{y}.png`
   `https://gisagent.mapgis.com/files/3d1fdf1a-cffd-4858-a65b-6223d1301061/tiles_2025/16/53945/40353.png`

### 显示

由于前端只能支撑3857等主流投影, 如果是非3857 (墨卡托投影的数据), 需要进一步和AI对话将其处理成前端可以直接使用的格式

> 你有没有把 tiff 统一处理成3857墨卡托投影呀, maplibre必须统一坐标系

前端会使用 maplireb/cesium 显示加载瓦片
