# 离线部署

> 一句话结论：以仓库 `skills/` 为分母共 **70** 个技能（63 个顶层 + 7 个 ui-ux 嵌套）。**48** 个在离线时仍会在底图或数据上断开，**22** 个无公网运行依赖。
> 断点已经不在前端库和注记字体：L1 / L3 残留已切到 `/lib/maplibre`、`/lib/cesium`、`/lib/fonts`。真正要准备的是 **天地图底图** 和 **可预抓的专题数据**。
> 数字来自 2026-11-25 对 `skills/` 的重扫，并计入 2026-11-26 的残留修复与专题预抓落地。逐技能矩阵见 OpenSpec change `offline-skill-network-deps-refresh`。
> 专题数据（不含瓦片）已落到打包机 `/data/dataset/gisagent`（936 文件 / 133.1 MiB / 32 技能目录），**尚未打进交付 tar**。天地图 / Terrarium / GIBS / Overture / 路由按策略不爬。

离线部署时最容易踩的坑是：只盯着“数据取不到”，却发现页面连地图都渲染不出来。原因分属不同环节——页面能不能起来取决于前端库，地图有没有背景取决于底图瓦片，标注有没有文字取决于字体服务，图上有没有内容才取决于数据接口。本章按这四个环节统计，并单独列出哪些数据可以提前爬取。

## 本章在离线交付中的位置

离线交付要同时回答“机器和网络怎么准备”和“技能会断在哪一环”。本章只回答后者：

- [部署方案与前提](/docs/offline-deploy-plan)：三机职责、端口、公网与局域网模型、客户准备清单。
- [x86 + 银河麒麟 V11](/docs/offline-deploy-kylin)：麒麟基线与现场闸门。
- [龙芯 + 统信 UOS](/docs/offline-deploy-loongarch)：龙芯基线、MapGIS 边界、B1 混合拓扑。
- [实施与运维要点](/docs/offline-deploy-ops)：三个离线包、验收判据、模型调用面联网矩阵。

本章的 L1–L6 是**制图产出面**的断点，手册的联网能力矩阵是**模型调用面**的可用性。两个口径不同，离线验收都要过。

## 部署检查清单

1. 确认产品 `/lib/maplibre/5.24.0`、`/lib/cesium/1.122`、`/lib/fonts` 在位。页面不应再请求 unpkg 或 Google Fonts。
2. 按现场 bbox 爬天地图，注入本地瓦片服务。底图请求应留在内网。
3. 能自建的先自建：路由、`postgis-poi-address`、本地 Overpass。
4. 专题包已在 `/data/dataset/gisagent`，随离线包分发时按技能目录拷入。瓦片和 Overture 仍按现场 bbox 另做。实时技能写截止时刻。
5. 新生成页面不要照抄 `maplibre-common` / `cesium-common` 的公网天地图示例。
6. 回归：逐个技能打开产物，确认无外部请求、有底图、有标注、有数据。

落地顺序：机器和网络按[部署方案与前提](/docs/offline-deploy-plan)打通之后，**先处理天地图底图与可预抓数据**，不要再把 L1 前端库当第一优先级。

## 边界与例外

- 规范类技能运行时不访问外网，但会引导新页面去引用在线底图。
- 实时性无法补偿：地震、台风、航班、潮位、临近雷达、气象预报、极光。
- 本章不覆盖「只放行部分域名」的白名单方案。若现场允许有限出网，优先保留底图与字体的本地化。
- `ui-ux-pro-max-skill` 按 7 个嵌套技能计数，不把 `cli/assets` 副本再算一遍。`mapgis10-java-skills` 的模块级 `SKILL.md` 不算独立技能。

## 复核方式

重跑：

```bash
python3 scripts/scan-skills-network-deps.py
```

脚本是静态第一遍，会把许可头和出处记录算进去，**不能直接当对外数字**。对外数字以人工复核为准，事实源是 `openspec/changes/offline-skill-network-deps-refresh/artifacts/ANALYSIS.md`。技能目录有增删时先跑脚本，再按该 change 的口径改本章名单。
